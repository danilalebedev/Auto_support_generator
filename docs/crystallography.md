# РСА и сборка нескольких серий

## Что реализовано

Generate принимает необязательный **CIF source**: папку или ZIP с подпапками по номерам соединений. CIF нужен только для соединений, для которых проведён РСА. Неизвестный номер, пустой выбранный источник или нечитаемый CIF останавливают сборку с описанием ошибки. Каждый структурный data-блок CIF обрабатывается отдельно.

После описания соединения вставляется рисунок структуры. Параметры эксперимента и таблицы располагаются в отдельном разделе **X-ray crystallography** перед приложением спектров. Исходные CIF не изменяются. Автоматическая нормализация некорректного старого списка авторов выполняется только в памяти и записывается в предупреждения.

## Что требуют журналы

Проверено 5 октября 2026 года. Это собственный шаблон программы на основании рекомендаций, а не официальный или гарантированно принимаемый ACS бланк.

| Источник | Существенные требования для этой функции |
| --- | --- |
| [ACS JOC](https://researcher-resources.acs.org/publish/author_guidelines?coden=joceah) | CIF, факторы структуры и checkCIF передаются в CCDC до подачи статьи. В SI приводятся параметры кристалла, ячейки и уточнения, рисунок тепловых эллипсоидов. В экспериментальной части описываются получение кристаллов, прибор, особенности уточнения, разупорядочение и определение абсолютной конфигурации, если применимо. |
| [ACS Crystal Growth & Design](https://researcher-resources.acs.org/publish/author_guidelines?coden=cgdefu) | Аналогичные требования к депонированию, валидации и описанию структуры; значимые для обсуждения длины связей и углы приводятся с погрешностями. |
| [IUCr Acta Crystallographica E](https://journals.iucr.org/e/services/notesforauthors.html) | Основой публикации служат CIF и структурные факторы; нужны условия роста, описание нетривиального уточнения, корректный маркированный рисунок и обработка замечаний checkCIF. |

Для обычной органической статьи по умолчанию используется краткая таблица, а не полный перечень атомных координат и геометрии. Фактические требования выбранного журнала всё равно проверяет автор. Программа не выполняет депонирование, не отправляет файлы на внешние серверы и не заменяет checkCIF.

## Подготовка файлов

```text
CIF_source/
  3c/
    sample.cif
    sample.json          # необязательные сведения автора
    ORTEP.png            # необязательный готовый рисунок
    sample.checkcif.pdf  # необязательный официальный отчёт
  3f/
    second.cif
```

Номера должны точно совпадать с Compound table. Старое размещение `Spectra_source/<номер>/cif/*.cif` поддерживается. Если выбран отдельный CIF source, используется именно он, без смешивания с CIF из спектров.

Сведения, которых нет в CIF, задаются в JSON с тем же именем:

```json
{
  "growth": "Single crystals were grown by slow evaporation from ethyl acetate at room temperature.",
  "refinement": "Describe disorder, solvent treatment and absolute configuration here when applicable.",
  "ccdc": "1234567",
  "image": "ORTEP.png",
  "caption": "Thermal ellipsoids are drawn at the 50% probability level; hydrogen atoms are omitted.",
  "include_geometry": false,
  "notes": "Additional experimental observations, if applicable."
}
```

Это пример синтаксиса, а не готовое описание вашего эксперимента. Введите реальные условия, номер депонирования и вероятность, использованную в рисунке. Незаполненные поля можно удалить.

| Поле | Назначение |
| --- | --- |
| `growth` | Условия получения кристаллов; не выводятся из формулы автоматически. |
| `refinement` | Авторское описание уточнения вместо `_refine_special_details`. |
| `ccdc` | Номер депонирования; если не задан, читается из CIF. |
| `image` | PNG/JPEG, путь относительно CIF. Например, экспорт ORTEP/Mercury/Olex2. |
| `caption` | Обязательная подпись для внешнего рисунка; программа не угадывает тип изображения. |
| `include_geometry` | `true` добавляет сохранённые в CIF длины связей и углы с исходными погрешностями и кодами симметрии. Новые погрешности не рассчитываются. |
| `notes` | Дополнительный текст автора. |

Для CIF с несколькими структурами общие значения задаются на верхнем уровне, индивидуальные в `"blocks": {"имя_data_блока": {...}}`. Номер соединения внутри текста можно обозначить `{Product.number}`: он сохранит связь при Patch и переоформлении.

**Изображения.** Без `image` создаётся координатная ball-and-stick визуализация асимметричной части ячейки без водородов. Она не является рисунком тепловых эллипсоидов. Связность оценивается по расстояниям; симметрическое достроение молекул и специальных позиций не выполняется. Такой рисунок предназначен для предварительной проверки, а для подачи структуры с анизотропным уточнением нужно предоставить корректный ORTEP. Программа явно сообщает об этом в отчёте. Исходный рисунок из вашего примера используется без перерисовки.

**Валидация.** Локально проверяются наличие полей, согласованность объёма ячейки, чисел отражений и R-факторов. Официальные A/B/C/G alerts извлекаются только из предоставленного `sample.checkcif.pdf` и сохраняются с отдельным источником в JSON. Отсутствие распознанных alerts не означает успешную официальную валидацию.

## Шаблон и результат

Поле **Crystallography template .docx** необязательно. Встроенный файл и редактируемая копия находятся в `src/si_generator/templates/Crystallography_template.docx` и `examples/example_4/Crystallography_template.docx`. В режиме Single all-in-one тот же шаблон можно поместить после метки `[AUTO SI: CRYSTALLOGRAPHY TEMPLATE]`; встроенная секция извлекается автоматически и имеет приоритет над отдельным полем.

| Алиас | Содержимое |
| --- | --- |
| `{Product.number}` | Номер соединения. |
| `{Product.name}` | Название из объекта продукта. |
| `{Crystal.block}` | Имя структурного data-блока CIF. |
| `{Crystal.ccdc}` | Номер депонирования. |
| `{Crystal.description}` | Методика, прибор, излучение, температура и сведения об уточнении. |
| `{Crystal.table}` | Основная таблица кристаллографических параметров. |
| `{Crystal.geometry}` | Дополнительная геометрия, если включена в JSON. |

Последние три алиаса ставятся отдельными абзацами. `{Crystal.table}` обязателен. Можно менять последовательность абзацев и заголовки. Произвольный дизайн таблиц и полная система журнальных шаблонов РСА пока не реализованы.

В `reports/crystallography/compound_N/` сохраняются исходные файлы, `crystallography.json`, рисунки и отдельный `crystallography.docx`. JSON содержит таблицы, происхождение данных и alerts; редактируемый общий SI находится в `docx`. Add и Patch копируют РСА-данные в новый output; перестановки не запускают CIF-парсер или MestReNova повторно.

## Несколько методик

Выберите **Multiple series** и **Series folder**. Порядок подпапок задаёт порядок серий; используйте префиксы `01_`, `02_`.

```text
Multiple_series/
  01_Method_A/
    Compound_table.docx
    SI_template.docx
    Reaction_schema.docx   # необязательно, только вместе со Scope
    Scope.docx
    Spectra_source.zip
    CIF_source/
  02_Method_B/
    Compound_table.docx
    SI_template.docx
    Spectra_source.zip
```

Для каждой серии обязательна только Compound table. Собственные шаблон, Reaction schema и Scope позволяют использовать разные методики и расчёты загрузок. Настройки Processing общие. Единые all-in-one файлы внутри пакетного режима пока не используются: нужны отдельные документы. Дубликаты номеров между сериями запрещены. Ошибка останавливает пакет, успешные промежуточные серии сохраняются для диагностики, но не выдаются за готовый общий SI.

В output находятся общий документ и manifest, а также подпапка `series` с исходными результатами каждой серии. Для расчёта загрузок в серии добавьте в её папку согласованные `Reaction_schema.docx` и `Scope.docx`.

## Проверочный пример

`examples/example_4` содержит 28 соединений из предоставленного support information, соответствующие raw `1H`/`13C` NMR, восемь наборов CIF с ORTEP и четыре исходных CIF-файла. `All_in_one_input.docx` включает SI template, Reaction schema, Scope и Crystallography template; `Spectra_source.zip` и `CIF_source` передаются отдельно.

[Reference_output.docx](../examples/example_4/Reference_output.docx) содержит фактический результат контрольного запуска с включённой опцией **Show scope**: рассчитанный scope, ЯМР-спектры и блоки РСА. Красные предупреждения ЯМР сохранены для ручной проверки пиков и интегралов. Это проверочный черновик, не готовый к публикации SI. Для Add/Patch заново соберите пример и используйте всю папку output, а не только этот DOCX.

Из исходников:

```powershell
python -m si_generator --all-in-one-input examples/example_4/All_in_one_input.docx --spectra-source examples/example_4/Spectra_source.zip --cif-source examples/example_4/CIF_source --output output/example_4/support_information.docx --insert-spectra-as png --insert-chemdraw --calculate-elemental-analysis --show-scope
```

Standalone РСА-only режим и универсальная система произвольных аналитических модулей не входят в эту итерацию.
